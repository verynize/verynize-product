## Dampak ke plan

- **Fase 0 tetap.** Urutan prioritas tidak berubah.
- **Tambahan Fase 0/1 (seleksi):** chrome seleksi multi-node menghitung bounding box dari model dokumen, bukan dari `getBoundingClientRect` per node. Ini perbaikan termurah untuk select all.
- **Tambahan Fase 0 (sync):** pakai jumlah node per halaman yang sudah ada di balasan `same:true` untuk mendeteksi divergensi sebelum hash isi tersedia.
- **Koreksi Sentry:** perbaikan DSN ditujukan ke plugin `load-env` TanStack Start. Event `render-process-gone` sebagian sudah terkirim, jadi yang perlu ditambahkan adalah status `crashed`/`oom`/`killed` dan jendela render.
- **Fase 1:** target zoom 10K perlu dimasukkan, karena 13-17 % frame telat.

## Masih terbuka

- Pemicu angka 904 di room AUDIT dan penyebab broadcast/ack hilang di production (`ws.send` yang ditelan di `rooms.js:225-227` belum terbukti; docs Cloudflare tidak menyebut kapan `send` melempar).
- Dari uji gesture: client web membuka room dengan salinan basi (4 node vs 8.904 di revisi yang sama), `location.reload()` di route room desktop menampilkan "Forbidden", dan heap desktop naik ke 1,75 GB setelah ~170 revisi. Masing-masing terlihat sekali dan belum ditelusuri.
- Screenshot: render offscreen yang keluar tanpa zoom/font (1/38) belum bisa direproduksi.
