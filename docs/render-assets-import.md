# Render, assets and Pen import

Raster screenshots bound output to 4096 CSS/output pixels per side, plus the existing 8192 physical pixel / 32 megapixel limits. Large document coordinates are accepted and the effective scale is returned. Exact-scale exports still reject oversized output. Before capture, the renderer checks the effective viewport/page zoom, a CSS zoom probe, font face readiness and image/background/mask decoding. It reapplies zoom and font CSS once if readiness fails; failure produces no image or measured boxes. Renderer/child failures report their phase and sanitized reason. Runtime file identity changes require restart. A tiny startup smoke render uses the same queue; PDF and raster share it.

`asset:<64 lowercase SHA-256 hex>` references immutable bytes. `integrations/asset-store.mjs` sanitizes SVG before hashing, checks MIME signatures and decoded storage size (20971520 bytes; HTML image imports and MCP file upload remain capped at 4194304 bytes), atomically stores one blob per hash, and verifies reads. File documents use `NAME.verynize.assets/<hash>`; desktop working documents use the user-data `assets` directory. Native open/save/save-as copy referenced assets before publishing JSON. Missing/corrupt sidecars produce an error without overwriting the source document. Browser storage is IndexedDB `verynize-assets`, with in-flight blob URL dedupe and pagehide revocation. No asset garbage collection is performed because history/undo may retain references.

Desktop and MCP HTML imports supply an asset sink for image nodes, CSS image fills and inline SVG. Pure codec callers may omit the sink to retain the legacy self-contained result. Legacy data URI documents remain valid. `upload_asset` accepts an absolute local image/font file path and returns metadata only. Before rendering, legacy signed room URLs are fetched under the shared room-asset URL schema with a byte/time cap and stored by hash. Hidden render sessions resolve only the hashes present in their HTML/font CSS through their own protocol. Portable MCP HTML and template-pack export explicitly inline assets before using existing encoders. Cloud sharing uploads hash references through the existing room-authorized SHA/R2 dedupe and replaces them with existing room URLs; a hash is never cloud authorization. Hosted MCP rejects local-file-only tools explicitly.

HTML source limits are 5000000 UTF-8 bytes on desktop, parser and MCP. Decoded inline images now count against the same per-resource and total budgets as files/network resources. Resource capacity errors abort conversion; preflight reports source bytes, decoded unique assets, document bytes, nodes and the exceeded limit without writing blobs/documents.

`import_pen` reads unencrypted JSON only. Supported explicit subset versions are `1.0` and `2.8`: top-level `children`, unique `id`, frame/group/rectangle/text/path/icon_font/ref nodes, `reusable`, `ref`, descendant overrides by slash-separated ID paths, numeric dimensions, free/horizontal/vertical layout, basic text/solid fills, clipping and hidden state. Lucide icons use the bundled icon library. Binary/encrypted inputs, unknown versions, cycles, invalid references and excessive nesting/expansion fail. Unsupported fields (including variables/themes, complex paints and sizing expressions) are reported as losses; this is not a claim of universal vendor-format compatibility. Tests use independently authored synthetic JSON only.

`finish_artboard(intent: "faithful-import")` requires unchanged HTML/Pen import evidence in the current MCP session. Only contrast findings on imported artboards are waived, with source digest and exact finding IDs. Structural findings remain blocking even after repair-budget exhaustion. Render verification and source fidelity are separate fields: without comparison evidence, fidelity is `unverified` (or `partial` for reported losses), even with a current screenshot. Evidence is intentionally conservative and expires after any edit/session restart.

Known boundaries: no generic encrypted Pen decoder, arbitrary vendor version support, staged/resumable imports or asset garbage collection. Browser-only transfer of native JSON sidecars requires uploading the referenced blobs to the offline store; JSON alone is not a portable asset bundle. Native template archives and MCP standalone HTML carry the bytes. Runtime fingerprint compares executable/framework/helper stat identity, not a cryptographic signature of an entire installed application.
